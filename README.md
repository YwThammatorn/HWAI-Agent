# ตัวอย่างแกนกลางการตรวจ — AI Agent ช่วยตรวจงาน UX/UI

โค้ดชุดนี้เป็น **ตัวอย่างเพื่อคุยกัน ไม่ใช่ระบบจริง** ทำขึ้นเพื่อตอบคำถามเดียวที่นักศึกษาติดกันมากที่สุด:

> **"แล้วเว็บของเรามันไปเชื่อมกับ LLM ยังไง"**

รันได้ทันทีบนโน้ตบุ๊กเครื่องไหนก็ได้ — **ไม่ต้องมี GPU ไม่ต้องมี API key ไม่ต้อง `npm install` ไม่ต้องต่อเน็ต**

```bash
node --experimental-strip-types src/demo.ts          # เดินทั้งท่อให้ดูทีละขั้น
node --experimental-strip-types --test test/*.test.ts   # 19 เทสต์
```

ต้องการ Node 22.6 ขึ้นไป (เครื่องที่เขียนนี้ใช้ v22.19.0) เพราะใช้ความสามารถของ Node ที่รัน TypeScript ได้ตรง ๆ
ไม่มี dependency แม้แต่ตัวเดียว — โฟลเดอร์นี้ไม่มี `node_modules` และไม่ต้องมี

## 1. คำตอบสั้น ๆ: มันคือ HTTP POST หนึ่งครั้ง

นี่คือจุดที่มักเข้าใจผิดกันมากที่สุด **เว็บของเราไม่ได้โหลดโมเดล**
ไม่ได้ `import torch` ไม่ได้แตะ CUDA ไม่มีไฟล์ weight อยู่ในโปรเจกต์เลย

```
   เบราว์เซอร์ของอาจารย์
       │  HTTPS
       ▼
   VM ของคณะ                                    ← โค้ดในโฟลเดอร์นี้อยู่ตรงนี้
   (Next.js + PostgreSQL + worker · TypeScript ล้วน)
       │
       │  HTTP ภายในคณะ
       │  POST http://<ip เครื่อง GPU>:8000/v1/chat/completions
       │  content-type: application/json
       ▼
   เครื่อง GPU (RTX 5090)                        ← ไม่มีโค้ดของเราอยู่เลยสักบรรทัด
   รันโปรแกรมชื่อ vLLM ซึ่งเป็นตัวโหลดโมเดล
```

ฝั่งเครื่อง GPU สั่งครั้งเดียวจบ แล้วปล่อยไว้:

```bash
vllm serve Qwen/Qwen2.5-VL-32B-Instruct \
    --port 8000 --max-model-len 16384 --quantization awq
```

vLLM จะเปิดพอร์ต HTTP ที่ "พูดภาษาเดียวกับ OpenAI API" ตั้งแต่วินาทีนั้น
หน้าที่ทั้งหมดของโค้ดเราจึงเหลือแค่ **ประกอบ JSON → ยิงไป → อ่าน JSON กลับมา**

รัน `demo.ts` แล้วดูขั้นที่ **[4]** — มันพิมพ์ JSON ก้อนจริงที่จะถูกยิงออกไปให้ดูกับตา
(ตัดก้อน base64 ของภาพให้สั้นลงเท่านั้น ที่เหลือคือของจริงทุกตัวอักษร)

### สามจุดที่คนถามซ้ำที่สุด

**ภาพเดินทางไปยังไง** — อยู่ใน `messages[].content` ซึ่งเป็น *อาร์เรย์ของบล็อก* ไม่ใช่สตริง
บล็อกชนิด `image_url` มีค่าเป็น data URI (`data:image/png;base64,...`)
ไม่ต้องอัปโหลดไฟล์ไว้ที่ไหนก่อน ไม่ต้องมี S3 ไม่ต้องมี URL สาธารณะ

**ทำไมมั่นใจว่าโมเดลจะตอบเป็น JSON** — เพราะส่ง `response_format` ที่มี JSON Schema ไปด้วย
vLLM ใช้ guided decoding คือ **จำกัดตัวเลือกของโมเดลตอนถอดรหัส** ให้เดินออกนอกโครงไม่ได้เลย
ไม่ใช่แค่ "เขียนขอร้องใน prompt" ซึ่งพังเป็นครั้งคราวเสมอเมื่อมีงานส่งเข้ามาหลายสิบชิ้น

**ทำไม `temperature: 0`** — เพราะเราต้องการผลที่ซ้ำได้ ไม่ได้ต้องการความสร้างสรรค์
ถ้าตรวจงานชิ้นเดิมสองครั้งได้คะแนนไม่เท่ากัน จะอธิบายกับนักศึกษาที่มาทักท้วงไม่ได้

### ถ้าจะเปลี่ยนไปใช้ API ข้างนอก

`src/judge.ts` มีตัวต่อสามตัว หน้าตาเหมือนกันหมดจากมุมของคนเรียก:

| ตัวต่อ | ใช้เมื่อไร | ต่อกับอะไร |
|---|---|---|
| `MockJudge` | พัฒนา / เขียนเทสต์ | ไม่ต่อกับอะไร ให้ผลเดิมทุกครั้ง |
| `VllmJudge` | **ตัวที่ใช้จริง** | เครื่อง GPU ของคณะ |
| `AnthropicJudge` | จุดเทียบระดับบนสุดตอนเขียนบทที่ 4 | API ภายนอก |

ต่างกันแค่รูปร่าง JSON: `image_url` ↔ `image.source.base64` และ `response_format` ↔ `tools`
ท่อที่เหลือทั้งเส้นไม่ต้องแก้ เพราะมีชนิดกลางชื่อ `GradingPrompt` คั่นไว้ (`src/prompt.ts`)

ชี้ไปที่ endpoint จริงแบบนี้:

```ts
const judge = new VllmJudge('http://10.0.0.9:8000', 'Qwen/Qwen2.5-VL-32B-Instruct');
const record = await grade(submission, rubric, judge);
```

## 2. ท่อทั้งเส้น

```
grade(submission, rubric, judge)
  0. ยามนโยบาย   assertMayLeaveFaculty()   ← งานนักศึกษาไม่ออกนอกคณะ
  1. ถอดตัวตน     anonymize()              ← ชื่อ / รหัส / ชื่อไฟล์ / folder_name
  2. ชั้นกฎ        scoreByRule()            ← contrast, ครบองค์ประกอบ — LLM ห้ามแตะ
  3. ชั้น LLM      judge.score()            ← จุดที่ต่อกับโมเดล
  4. รวม + สืบย้อน merge + trace[]          ← ใครให้คะแนน ด้วยอะไร เมื่อไร
     → status: 'awaiting-instructor'        ← นักศึกษายังไม่เห็น
```

| ไฟล์ | หน้าที่ |
|---|---|
| `src/types.ts` | ชนิดข้อมูลกลาง — `Submission` กับ `AnonymizedSubmission` เป็นคนละชนิดโดยตั้งใจ |
| `src/anonymize.ts` | ถอดตัวตน + คืน "รายการสตริงต้องห้าม" ให้ด่านหลังตรวจซ้ำ |
| `src/rules.ts` | คณิตศาสตร์ WCAG contrast ของจริง + แปลงผลกฎเป็นคะแนน |
| `src/prompt.ts` | ประกอบ prompt + **ด่านสุดท้าย** ก่อนข้อมูลออกจากเครื่อง |
| `src/judge.ts` | **จุดที่ต่อกับ LLM** — สามตัวต่อ + ตัวตรวจคำตอบ |
| `src/grade.ts` | ตัวเดินท่อ ฟังก์ชันเดียวที่ฝั่งเว็บเรียก |
| `src/demo.ts` | พิมพ์ทุกขั้นให้ดู |
| `fixtures/rubric.ts` | rubric สมมติ 4 เกณฑ์ + งานสมมติที่ตั้งใจใส่กับดักไว้ |

## 3. การตัดสินใจสามข้อที่อยากให้ถกเถียง

โค้ดนี้ตัดสินใจไปแล้วสามเรื่อง ทุกเรื่องเปลี่ยนได้ แต่ต้องรู้ว่าแลกกับอะไร

### 3.1 ผลของชั้นกฎ **ไม่** ถูกใส่เข้าไปใน prompt

ใส่แล้วสะดวกกว่า โมเดลจะได้รู้ว่าคอนทราสต์ตกไปกี่จุด
แต่มันคือการ anchor — โมเดลที่เห็นว่า "ชั้นกฎบอกว่างานนี้แย่" มีแนวโน้มให้คะแนนเกณฑ์อื่นต่ำตาม
แล้วเราจะแยกไม่ออกว่าคะแนนที่ได้มาจากการดูงาน หรือมาจากการเห็นคะแนนอื่นมาก่อน
ซึ่งทำให้ตัวเลขในบทที่ 4 ตอบคำถามคนละข้อกับที่ตั้งใจถาม

### 3.2 ชั้นกฎรับ **ข้อมูลดิบ** ไม่ใช่ข้อมูลที่ถอดตัวตนแล้ว

ฟังดูย้อนแย้ง แต่ชั้นกฎคำนวณอยู่บนเครื่องคณะ ไม่ได้ส่งอะไรออกไปไหนเลย
การถอดตัวตนก่อนจึงไม่ได้เพิ่มความปลอดภัยแม้แต่นิดเดียว มีแต่ทำให้ตรวจผิด

ตัวอย่างที่เกิดขึ้นได้จริงง่ายมาก: นักศึกษาชื่อเล่น **"Bank"** กับโจทย์ที่สั่งให้มีหน้าจอชื่อ **"Bank"**
ถ้าถอดตัวตนก่อน ชื่อเฟรมจะกลายเป็น `[ถอดออก]` แล้วกฎหาไม่เจอ
นักศึกษาเสียคะแนนเพราะการถอดตัวตนของเราเอง ไม่ใช่เพราะงานที่เขาทำ
(มีเทสต์คุมไว้แล้วใน `test/rules.test.ts` — ถ้ามีคนย้ายลำดับ เทสต์จะแดงพร้อมคำอธิบาย)

### 3.3 คะแนนจากกฎ **ปัดลง** ไม่ใช่ปัดใกล้สุด

เพราะระดับใน rubric มีความหมายว่า "ทำได้อย่างน้อยเท่านี้" ผ่าน 75% จึงได้ระดับ 2 ไม่ใช่ระดับ 3

## 4. นโยบายที่ถูกบังคับด้วยโค้ด ไม่ใช่ด้วยความจำ

ข้อบังคับจาก ticket 18 และเอกสาร 01 §4.4 ถ้าอยู่แค่ในเอกสารก็คือคำพูด
สามข้อนี้จึงเขียนเป็นโค้ดที่ **โยน error** ไม่ใช่คืนค่าให้คนเรียกเลือกจะเช็กหรือไม่เช็ก

| กฎ | บังคับที่ไหน | เทสต์ |
|---|---|---|
| ข้อมูลระบุตัวตนห้ามหลุดเข้า prompt | `assertClean()` ใน `buildPrompt()` | `anonymize.test.ts` |
| งานนักศึกษาไม่ออกนอกคณะถ้าไม่ได้ยินยอมรายชิ้น | `assertMayLeaveFaculty()` | `grade.test.ts` |
| LLM ให้คะแนนนอกระดับที่ rubric นิยามไม่ได้ | `parseAndValidate()` | `grade.test.ts` |

รหัสแทนตัว (`S-2e612ace`) **สุ่มใหม่ทุกครั้ง** ห้าม derive จากรหัสนักศึกษาแม้ผ่าน hash
เพราะ hash ที่คงที่แปลว่าเชื่อมโยงข้ามครั้งได้ = ระบุตัวตนโดยพฤตินัย

### ข้อจำกัดที่ห้ามกลบ

ระบบถอดได้เฉพาะ **ข้อมูลระบุตัวตนที่ระบบถืออยู่ในฐานะข้อความ**
ถ้านักศึกษาพิมพ์ชื่อตัวเองลงไปในภาพ mockup แล้ว export เป็น PNG ชื่อนั้นอยู่ในพิกเซล ไม่ใช่ในสตริง
โค้ดนี้มองไม่เห็นและถอดไม่ได้

ดังนั้นนโยบายพูดได้แค่ว่า *"ไม่ส่งข้อมูลระบุตัวตนที่ระบบถืออยู่"*
พูดว่า *"โมเดลไม่มีทางรู้ว่าใครทำ"* **ไม่ได้** — มีเทสต์ตัวหนึ่งเขียนไว้เพื่อกันไม่ให้ใครเผลอเขียนแบบนั้น

## 5. อะไรจริง อะไรปลอมในตัวอย่างนี้

| ส่วน | สถานะ |
|---|---|
| คณิตศาสตร์ WCAG contrast | **ของจริง** ตรงตามนิยาม WCAG 2.x เทียบกับค่ามาตรฐานได้ |
| รูปร่าง request ของ vLLM / Anthropic | **ของจริง** เขียนตามสเปกของทั้งสองเจ้า |
| ท่อทั้งเส้น ลำดับขั้น ยามนโยบาย ตัวตรวจคำตอบ | **ของจริง** รันได้ ทดสอบแล้ว |
| **ยังไม่เคยยิงเข้าเครื่อง GPU จริง** | ⚠ **ยังไม่พิสูจน์** — ยังไม่มีเครื่อง GPU ให้ทดสอบ |
| คะแนนจาก `MockJudge` | **ปลอม** มันไม่ได้ดูภาพด้วยซ้ำ ห้ามเอาไปเขียนในรายงาน |
| rubric 4 เกณฑ์ | **สมมติ** ของจริงต้องมาจาก rubric ที่อาจารย์ใช้สอนจริง |
| ตัวอ่านไฟล์ Figma / PDF | **ไม่มีในตัวอย่างนี้** สมมติว่ามีคนแปลงมาให้แล้ว |
| คิว, ฐานข้อมูล, หน้าจอ, การยืนยันของอาจารย์ | **ไม่มีในตัวอย่างนี้** อยู่ในเอกสาร 01 กับ 04 |

สิ่งที่ควรทำเป็นอย่างแรกเมื่อได้เครื่อง GPU: เอา `VllmJudge` ยิงเข้า endpoint จริงหนึ่งครั้ง
ถ้ารูปร่าง JSON ที่เขียนไว้ผิดจากที่ vLLM รับจริง จะรู้ทันทีในนาทีนั้น ไม่ใช่ตอนใกล้ส่งเล่ม
